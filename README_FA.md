# مرحله هفتم: تست یکپارچه APG Medicine Management

این بسته **فایل‌های عملیاتی پروژه را تغییر نمی‌دهد**. قبل از انتشار نسخه مشتری، تمام مراحل اول تا ششم باید روی آخرین نسخه محلی یکپارچه شوند. ZIPهای مستقل لزوماً قابل جایگزینی بدون تداخل نیستند.

## اجرای تست اولیه در Windows PowerShell

در حالی که API روی پورت 5000 اجرا می‌شود:

```powershell
powershell -ExecutionPolicy Bypass -File .\Check-APG.ps1 -ProjectPath 'D:\Delpha-farm'
```

تست Syntax، Build Production، وضعیت API، حالت PostgreSQL، حفاظت درخواست بدون Cookie و ارجاعات LocalStorage/IndexedDB را بررسی می‌کند. از روی موارد LocalStorage نمی‌توان خودکار حکم داد که دیتا تجارتی است یا ترجیحات ظاهری.

## تست‌های عملی ضروری روی دیتابیس **آزمایشی**

1. ساخت کاربر محدود و آزمایش دیدن/ساخت/ویرایش/حذف/چاپ هر بخش، هم در UI هم درخواست مستقیم API.
2. ثبت فروش در یک مرورگر و کنترل موجودی در مرورگر دیگر؛ اطمینان از یک‌بار ثبت شدن فاکتور.
3. تلاش دو کاربر برای فروش هم‌زمان آخرین موجودی؛ موجودی منفی نباید ایجاد شود.
4. قطع عمدی API پیش از Commit در دیتابیس آزمایشی؛ تمام تغییرات تراکنش باید Rollback شوند.
5. برگشت خریداری/فروشات و بازیابی سطل زباله؛ حساب و موجودی باید متوازن بمانند.
6. Preview فایل ACCDE واقعی؛ بررسی شمارش جدول‌ها و تطبیق رکوردها بدون Import واقعی.
7. Import رکورد با ID تکراری و اطلاعات متفاوت؛ باید Conflict دریافت شود و داده قبلی حفظ شود.
8. تهیه Backup، بازیابی روی دیتابیس آزمایشی، و تطبیق تعداد/مبالغ رکوردها.
9. انقضای Session؛ درخواست‌ها باید خطای دسترسی دهند، نه ذخیره محلی.
10. تست هم‌زمان دو مرورگر پس از Refresh کامل.

## مواردی که هنوز تأیید نشده‌اند

- Build کامل روی آخرین پروژه نصب‌شده کاربر
- اجرای تست End-to-End بر PostgreSQL واقعی
- آزمایش موتور Access ویندوز
- تأیید اینکه تمام اصلاحیه‌های قبلی در فایل‌های محلی باهم ادغام شده‌اند

این بسته از اجراکردن عملیات Import، DELETE، UPDATE یا INSERT خودداری می‌کند.
