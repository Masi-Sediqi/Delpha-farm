# مرحله دوم: آماده‌سازی PostgreSQL (نسخه آزمایشی و غیرعمومی)

1. محتویات ZIP را در ریشه پروژه Paste کن. پوشه‌های دیگر را حذف نکن.
2. این فایل فقط زیرساخت ذخیره‌سازی را تغییر می‌دهد؛ **ورود امن کاربران هنوز آماده نیست و نباید سیستم را عمومی منتشر کنی**.
3. PostgreSQL را در VPS با دیتابیس و یوزر اختصاصی بساز. نام پیشنهادی: apg_medicine_private و apg_medicine_app. برای ساخت نقش و دیتابیس، از یک رمز منحصر‌به‌فرد قوی استفاده کن.
4. `transport-backend/.env.example.vps` را به `transport-backend/.env` کپی کن و رمز واقعی را فقط داخل VPS بگذار. این فایل را در Git منتشر نکن.
5. روی VPS، از پوشه پروژه `npm ci` سپس `npm run build:production` را اجرا کن. Backend را با `node transport-backend/server.js` اجرا کن.
6. برای تست خصوصی، با SSH تونل به پورت 5000 دسترسی بگیر و `curl http://127.0.0.1:5000/api/health` را بررسی کن؛ باید `storage: postgresql` باشد.
7. در آینده پس از احراز هویت واقعی، Nginx `/api/` را به `127.0.0.1:5000` وصل می‌کند و فایل‌های `dist/` را ارائه می‌دهد. الان API را در اینترنت باز نکن.
8. هنوز Backup مرورگر را به دیتابیس وارد نکن. انتقال و احراز هویت در مرحله بعد اجرا می‌شود.
9. تغییرات آزمایشی روی نسخه اصلی کار نکن؛ ابتدا روی کپی پروژه تست کن.

## هشدارها
- فعال شدن حالت سروری، داده‌های قدیمی IndexedDB را به صورت خودکار کپی نمی‌کند؛ این رفتار برای جلوگیری از اختلاط و از دست رفتن اطلاعات عمدی است.
- هم‌زمانی با If-Match محافظت می‌شود اما هنوز فرم‌های دارای تغییرات چندمرحله‌ای و تمام APIها برای استفاده عمومی بررسی نشده‌اند.
- APIهای GET فاقد احراز هویت هستند. فقط آدرس loopback استفاده شود و حتی به صورت عمومی از طریق Nginx در دسترس قرار نگیرد.
- واردکردن Microsoft Access به طور موقت غیرفعال شده است.
- دیتابیس‌های دیگر VPS را دست نزن.
